# iOS-версия: сборка и проверка на Mac

Всё, что можно сделать без Mac, уже сделано и проверено на Windows
(см. «Что уже проверено» ниже). Mac нужен для одного прогона: собрать
приложение, увидеть **все** ошибки сразу и поставить его на iPhone.

## Что есть в iOS-версии

Приложение работает с тем же ядром, что Android, — шифрование,
протокол и хранилище у них общие. Экраны:

* регистрация: имя и почта → PIN (дважды) и выбор сети → код из письма;
* вход по PIN: задержки после неверных попыток (та же таблица, что на
  Android), стирание после 10 неверных — по желанию;
* список чатов, запросы от незнакомцев (принять/отклонить);
* переписка: отправка, статусы доставки, предупреждения о смене ключа
  и неподтверждённом ключе, блокировка;
* новый контакт: по имени, по ссылке, по QR (камера), свой QR и ссылка;
* код безопасности: QR, сравнение сканированием, отметка «сверен»;
* настройки: Tor или напрямую, стирание после 10 PIN, документы,
  **удаление аккаунта** (обязательно для App Store).

Защита — как на Android: ключ базы из PIN (Argon2id) **и** ключа
Secure Enclave, который не покидает телефон; пиннинг ключа TLS
сервера; без кеша и cookie; шторка в переключателе приложений;
автоблокировка через 30 секунд в фоне.

**Пока нет** (следующие шаги): каналы, вложения (фото), резервная копия
и восстановление, уведомления при закрытом приложении (нужно решение
про пуш-уведомления Apple — см. конец), Face ID.

### Что уже проверено без Mac

* Ядро собирается, биндинги Swift генерируются из настоящей сборки.
* Слой без интерфейса (ядро, сеть, ключ базы, PIN, правила отправки)
  **компилируется и проходит 16 тестов против настоящего ядра**
  (`tools/ios-kit-test.sh` в контейнере Swift): открытие базы по PIN,
  отказ при неверном PIN, транспорт, режимы сети, ожидающая регистрация.
* Синтаксис всех Swift-файлов, включая экраны.

**Не проверено** (только на Mac): компиляция экранов SwiftUI, Keychain
и Secure Enclave, пиннинг на настоящем сертификате, Tor на iOS, вид
экранов.

## Часть 1. Архив для Mac (на ПК)

🪟 PowerShell, папка проекта. Сначала закоммитьте изменения: в архив
попадает только то, что в git.

```powershell
cd C:\Users\be4ho\Desktop\WORK\AEGIS
git log -1 --oneline | Set-Content -Encoding utf8 "$env:TEMP\COMMIT.txt"
git archive --format=zip --prefix=gasapp/ --add-file="$env:TEMP\COMMIT.txt" -o "$HOME\Desktop\gasapp-mac.zip" HEAD
```

🔐 В архиве нет секретов: ключи и пароли — на флешке и в Bitwarden.

## Часть 2. На Mac

### Что нужно

* Mac на Apple Silicon (M1 и новее) или Intel, macOS 14+, ~25 ГБ места.
* **Xcode** из App Store.
* Для установки на iPhone — кабель и ваша учётная запись Apple
  Developer (Team ID: developer.apple.com → Account → Membership).

### Шаг 1. Xcode

1. App Store → **Xcode** → установить. Открыть один раз, согласиться
   с лицензией, отметить платформу **iOS**.
2. Для iPhone: Xcode → *Settings* → *Accounts* → «+» → войти своим
   Apple ID (тем, что в Apple Developer).
3. Закрыть Xcode.

### Шаг 2. Проверка в симуляторе

Распаковать `gasapp-mac.zip` в «Загрузках». Terminal:

```bash
sudo xcode-select -s /Applications/Xcode.app
cd ~/Downloads/gasapp
bash tools/mac-check.sh
```

* Спросит про установку Rust — `y` (ставится в домашнюю папку).
* Поставит XcodeGen (через Homebrew или скачает с GitHub).
* Первая сборка ядра — 15–30 минут.
* Откроется Simulator: приложение само откроется на каждом экране,
  снимки лягут в `mac-report/screens/`.

### Шаг 3. На ваш iPhone

1. iPhone — кабелем к Mac, разблокировать, «Доверять этому компьютеру».
2. На iPhone: *Настройки* → *Конфиденциальность и безопасность* →
   **Режим разработчика** → включить (телефон перезагрузится).
3. Terminal:

```bash
bash tools/mac-check.sh --device ВАШ_TEAM_ID
```

Приложение появится на телефоне. Если при запуске iPhone пишет
«Ненадёжный разработчик» — *Настройки* → *Основные* → *VPN и управление
устройством* → ваш профиль → «Доверять».

> ⚠️ Пины в сборке — заглушки, пока не впишете настоящие
> (`ios/Config/Local.xcconfig`, образец — `Local.xcconfig.example`):
> приложение откроется и покажет экраны, но к серверу не подключится.
> Так и задумано: заглушка не выглядит рабочей настройкой.

### Шаг 4. Отчёт

В конце — итог по шагам и архив **`~/Downloads/gasapp/mac-report.zip`**.
Его — разработчику:

| Файл | Что внутри |
|---|---|
| `SUMMARY.txt` | Итог по каждому шагу |
| `swift-errors.txt` | **Все** ошибки Swift сразу: `файл:строка: текст` |
| `build-errors.txt` | Ошибки сборки Xcode и компоновки |
| `rust-errors.txt` | Ошибки сборки ядра |
| `screens/*.png` | Снимок каждого экрана |
| `console-*.txt`, `app-log.txt`, `crashes/` | Вывод, журнал, падения |

### Если что-то пошло не так

| Сообщение | Что сделать |
|---|---|
| `Не найден Xcode` | Шаг 1, затем `sudo xcode-select -s /Applications/Xcode.app` |
| `Симулятор iOS: НЕТ` | Xcode → Settings → Components → iOS → Get |
| `XcodeGen не установился` | `brew install xcodegen` (Homebrew — brew.sh) |
| `No signing certificate` / `No profiles` | Шаг 1.2: войти в Xcode своим Apple ID; Team ID — верный |
| `iPhone не найден` | Кабель, разблокировать, «Доверять», Режим разработчика |
| `No space left on device` | Освободить место, удалить `gasapp/crates/target` |

## Решение за владельцем: уведомления

iOS не даёт приложению работать в фоне. Пока GasApp открыт, он сам
забирает сообщения каждые несколько секунд. **Когда приложение закрыто,
узнать о новом сообщении можно только через пуш-уведомления Apple
(APNs)** — то есть через серверы Apple, а не напрямую.

Варианты:

1. **APNs без содержимого** (рекомендую): сервер шлёт через Apple только
   «проснись», без текста, имени и отправителя; телефон сам забирает
   сообщение и показывает уведомление. Apple видит лишь факт, что
   устройству что-то пришло, и время.
2. **Без уведомлений на iOS**: сообщения — только при открытом
   приложении. Максимально приватно, но неудобно.

На Android уведомления работают без Google (ADR-040); для iOS такого
пути у Apple нет.
