# Обновить сайт, письма, админ-центр и Telegram до шага 24

> ➡️ **Сайт и мониторинг теперь обновляются одной командой** в Ubuntu:
> `bash /mnt/c/Users/be4ho/Desktop/WORK/AEGIS/server/deploy/update-servers.sh`
> — сайт, скрипты монитора (оповещения по-русски), `68/udp`,
> контрольные суммы со сверкой программ, перезагрузка по запросу.
> Спросит фразу ключа SSH один раз и пароль `ops` на каждой машине.

Делайте после того, как шаги 18–23 уже выполнены. Команды ниже идут в
**окне Ubuntu 24.04 (WSL) на ПК**, кроме явно обозначенных проверок в
браузере. SSH-имена `gasapp-lb`, `gasapp-node2`, `gasapp-node3`,
`gasapp-db` — из шага 23.1. Окно с отдельным туннелем `ssh -N -L ...`
можно оставить открытым: эти команды выполняются **в другом окне**.
Копируйте **только команды внутри блоков**. Строки с тремя обратными
кавычками (начало и конец блока Markdown) в терминал не вставляйте.

Новые токены и ключи создавать не нужно; `sudo` на VPS может попросить
действующий пароль `ops`. Файлы на Windows — актуальная версия проекта
в редакторе; старая копия `~/gasapp` в WSL получит исходники
админ-центра для сборки.

## 1. Собрать новый админ-центр

```bash
source ~/.gasapp-env
WIN=/mnt/c/Users/be4ho/Desktop/WORK/AEGIS
cp "$WIN/server/gasapp-server-admin/src/lib.rs" "$REPO/server/gasapp-server-admin/src/lib.rs"
cp "$WIN/server/gasapp-server-admin/src/main.rs" "$REPO/server/gasapp-server-admin/src/main.rs"
cp "$WIN/server/gasapp-server-admin/src/queries.rs" "$REPO/server/gasapp-server-admin/src/queries.rs"
cp "$WIN/server/gasapp-server-admin/src/style.css" "$REPO/server/gasapp-server-admin/src/style.css"
cd "$REPO/server"
cargo build --release --locked -j 2 -p gasapp-server-admin
rsync -a target/release/gasapp-server-admin gasapp-db:~/gasapp-server-admin.new
```

На БАЗЕ установить и перезапустить службу:

```bash
ssh -t gasapp-db 'sudo install -m 755 ~/gasapp-server-admin.new /usr/local/bin/gasapp-server-admin.new && sudo mv /usr/local/bin/gasapp-server-admin.new /usr/local/bin/gasapp-server-admin && sudo systemctl restart gasapp-admin && systemctl is-active gasapp-admin && rm ~/gasapp-server-admin.new'
```

Ожидается `active`. Исправление формы входа `Origin: null` тоже входит
в этот бинарный файл.

## 2. Обновить сайт

```bash
source ~/.gasapp-env
WIN=/mnt/c/Users/be4ho/Desktop/WORK/AEGIS
python3 "$WIN/tools/build-site.py" --out /tmp/gasapp-site --base-url https://gasapp.eu
rsync -a --delete /tmp/gasapp-site/ gasapp-lb:site/
ssh -t gasapp-lb 'sudo rsync -a --delete --chown=root:root --chmod=D755,F644 ~/site/ /var/www/gasapp-site/ && sudo nginx -t && sudo systemctl reload nginx'
curl -fsS https://gasapp.eu/ | grep -qF 'Make space for better conversations.' && echo 'Site updated'
```

Последняя команда должна напечатать `Site updated`. Каталог документов
находится по `/documents/` и `/ru/documents/`; страницы политики,
условий и поддержки лежат по прежним адресам. Для сайта не
нужно пересобирать Android-приложение. Предупреждения nginx
`protocol options redefined` при успешном `nginx -t` не останавливают
выкладку: новый заголовок по HTTPS — проверка, что сайт обновился.

Если письма, Telegram и монитор уже обновлены и нужно выложить **только
новый интерфейс**, достаточно шагов 1 и 2. После установки админ-центра
обновите контрольные суммы **только на `gasapp-db`**:

```bash
ssh -t gasapp-db 'sha256sum /usr/local/bin/gasapp-server-* /opt/gasapp/*.sh /opt/gasapp/*/*.sh 2>/dev/null | sudo tee /etc/gasapp/checksums.sha256 >/dev/null && sudo sha256sum -c /etc/gasapp/checksums.sha256'
```

Шаги 3 и 4 для одного лишь оформления повторять не требуется.

## 3. Разослать новые скрипты

```bash
source ~/.gasapp-env
WIN=/mnt/c/Users/be4ho/Desktop/WORK/AEGIS
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    rsync -a "$WIN/server/deploy/notify-telegram.sh" "$h:deploy/notify-telegram.sh" || break
    rsync -a "$WIN/server/deploy/monitor/gasapp-monitor.sh" "$h:deploy/monitor/gasapp-monitor.sh" || break
    printf '%s\n' "$h" | ssh "$h" 'cat > "$HOME/node-label.new"' || break
done
for h in gasapp-lb gasapp-node2 gasapp-node3; do
    rsync -a "$WIN/server/deploy/mail/send-code.sh" "$h:deploy/mail/send-code.sh" || break
done
rsync -a "$WIN/server/deploy/check-nodes.sh" gasapp-lb:deploy/check-nodes.sh
rsync -a "$WIN/server/deploy/certbot/gasapp-cert.sh" gasapp-lb:deploy/certbot/gasapp-cert.sh
```

Если какая-либо команда `rsync` завершилась ошибкой, исправьте её до
следующего блока. **Шаг 4 нельзя запускать до шага 3:** файл
`~/node-label.new` должен быть на каждом VPS. Скрипты пока лежат в
домашних каталогах; активные службы ещё используют старые копии.

Если скрипты уже скопированы, но шаг 4 показал
`cannot stat '/home/ops/node-label.new'`, **не повторяйте весь шаг 3**.
Отправьте только недостающие имена узлов:

```bash
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    printf '%s\n' "$h" | ssh "$h" 'cat > "$HOME/node-label.new"' || break
done
```

Успешная команда не печатает ничего. После неё повторите шаг 4.

## 4. Установить скрипты на VPS

Повторить **один блок** для каждого имени. Он может попросить пароль
`sudo` на соответствующем VPS:

```bash
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    ssh -t "$h" '
        set -e
        for file in ~/deploy/notify-telegram.sh ~/deploy/monitor/gasapp-monitor.sh ~/node-label.new; do
            if [ ! -s "$file" ]; then
                echo "Missing $file — run step 3 first" >&2
                exit 1
            fi
        done
        sudo install -m 755 ~/deploy/notify-telegram.sh /opt/gasapp/notify-telegram.sh
        sudo install -m 755 ~/deploy/monitor/gasapp-monitor.sh /opt/gasapp/monitor/gasapp-monitor.sh
        sudo install -m 644 ~/node-label.new /etc/gasapp/node-label
        printf "Telegram alerts are working\n" | sudo /opt/gasapp/notify-telegram.sh
        rm ~/node-label.new
    ' || break
done
```

В Telegram должны прийти четыре сообщения с **разными** заголовками:
`[GasApp / gasapp-lb]`, `[GasApp / gasapp-node2]`, `[GasApp / gasapp-node3]`,
`[GasApp / gasapp-db]`. Если цикла прервётся, устраните ошибку и
повторите: установка этих файлов безопасна при повторе.

Письмо с кодом — на трёх узлах API:

```bash
for h in gasapp-lb gasapp-node2 gasapp-node3; do
    ssh -t "$h" 'sudo install -m 755 ~/deploy/mail/send-code.sh /opt/gasapp/mail/send-code.sh' || break
done
```

Скрипт вызывается сервером для каждого нового письма: перезапуск API
не нужен. Старые уже отправленные письма не меняются.

На VPS-1 установить проверку узлов и оповещения о сертификатах:

```bash
ssh -t gasapp-lb 'sudo install -m 755 ~/deploy/check-nodes.sh /opt/gasapp/check-nodes.sh && sudo install -m 755 ~/deploy/certbot/gasapp-cert.sh /opt/gasapp/certbot/gasapp-cert.sh'
```

Если сайт и монитор уже были установлены из более ранней версии этих
исходников, выполните блок ниже **один раз** перед шагом 5. Он собирает
только статический сайт, а на VPS заменяет только скрипт монитора. Rust,
Android, базу данных, ключи и остальные службы пересобирать не требуется:

```bash
source ~/.gasapp-env
WIN=/mnt/c/Users/be4ho/Desktop/WORK/AEGIS
python3 "$WIN/tools/build-site.py" --out /tmp/gasapp-site --base-url https://gasapp.eu
rsync -a --delete /tmp/gasapp-site/ gasapp-lb:site/
ssh -t gasapp-lb 'sudo rsync -a --delete --chown=root:root --chmod=D755,F644 ~/site/ /var/www/gasapp-site/ && sudo nginx -t && sudo systemctl reload nginx'
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    rsync -a "$WIN/server/deploy/monitor/gasapp-monitor.sh" "$h:deploy/monitor/gasapp-monitor.sh" || break
    ssh -t "$h" 'sudo install -m 755 ~/deploy/monitor/gasapp-monitor.sh /opt/gasapp/monitor/gasapp-monitor.sh' || break
done
curl -fsS https://gasapp.eu/ | grep -qF '>Russian</a>' && echo 'English site updated'
```

Должно появиться `English site updated`; если на каком-то VPS возникла
ошибка SSH/rsync, продолжите с этого имени после восстановления связи.
После установки всех скриптов выполните шаг 5 для обновления контрольных
сумм. Отдельные страницы `/ru/` останутся русскими — это самостоятельная
версия сайта; английская главная и английские документы проверяются при
сборке на непереведённые строки.

На IONOS DHCP-клиент может слушать `68/udp`. **После проверки**, что
`sudo ss -Hlunp 'sport = :68'` на каждой машине показывает
`systemd-networkd` или `dhclient`, добавьте его в список ожидаемых
портов монитора. В вашей установке это уже подтверждено на всех четырёх VPS:

```bash
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    ssh -t "$h" "sudo sed -i '/^GASAPP_ALLOWED_PORTS=/ { /68\/udp/! s/\"$/ 68\/udp\"/; }' /etc/gasapp/monitor.env && grep '^GASAPP_ALLOWED_PORTS=' /etc/gasapp/monitor.env && sudo systemctl start gasapp-monitor.service" || break
done
```

Команда идемпотентна: при повторе `68/udp` не дублируется. Она меняет
только предупреждение монитора, не правила брандмауэра.

## 5. Обновить контрольные суммы и проверить

Монитор сверяет суммы программ и скриптов. После планового обновления
запишите новые суммы **на каждом** VPS:

```bash
for h in gasapp-lb gasapp-node2 gasapp-node3 gasapp-db; do
    ssh -t "$h" 'sha256sum /usr/local/bin/gasapp-server-* /opt/gasapp/*.sh /opt/gasapp/*/*.sh 2>/dev/null | sudo tee /etc/gasapp/checksums.sha256 >/dev/null && sudo sha256sum -c /etc/gasapp/checksums.sha256 && sudo systemctl start gasapp-monitor.service' || break
done
```

Проверка `sha256sum -c` должна показать `OK` для каждого файла.
После установки отправьте письмо на **свой** адрес по примеру шага 16.4
и проверьте английский текст, HTML-оформление и код. Вход в админ-центр
через `http://127.0.0.1:8480/` — как в шаге 20.3. Следующий вход по
SSH на любой VPS должен дать в Telegram `SSH login: ops` под заголовком
**именно этого VPS** (монитор проверяет журнал раз в две минуты). Ежедневный
сигнал теперь перечисляет открытые проблемы. На БАЗЕ он также правильно
учитывает успешную копию, даже когда файл отметки доступен только
владельцу `postgres`.

После этих проверок можно вернуться к **шагу 24** основной инструкции.
