# Google Play: что можно подготовить до шага 24

Состояние на 26 октября 2026 года. **Создать аккаунт разработчика и
черновик приложения можно сейчас. Отправлять приложение на проверку пока
рано:** нужен выпускной AAB из шага 24, реальные TLS-пины, тестовые
аккаунты, графика и веб-способ запроса удаления аккаунта.

## 1. Аккаунт разработчика

Откройте [Play Console](https://play.google.com/console/). Google требует
Google-аккаунт владельца, возраст не менее 18 лет, принятие соглашения и
разовый регистрационный сбор **US$25**. Выберите тип аккаунта по реальному
владельцу приложения:

* **Личный:** юридическое имя и адрес из платёжного профиля, имя
  разработчика для витрины, рабочие контактные email и телефон.
* **Организация:** юридическое название и адрес организации, **D-U-N-S**,
  сайт организации, контактные email и телефон. D-U-N-S получают бесплатно,
  но проверка может занять время.

Google проверяет личность. Данные владельца и документы для проверки
берутся из ваших реальных данных — их нельзя выдумать или брать из кода.
Для нового **личного** аккаунта понадобится также подтвердить доступ к
настоящему Android-телефону (Android 10+, без root) через приложение Play
Console; эмулятор не подойдёт. Для организации Google проверяет сайт.
Подробности: [регистрация](https://support.google.com/googleplay/android-developer/answer/6112435),
[данные аккаунта](https://support.google.com/googleplay/android-developer/answer/13628312),
[проверка устройства](https://support.google.com/googleplay/android-developer/answer/14316361).

## 2. Создать черновик приложения

В Play Console: **Home → Create app**. Значения, подтверждённые проектом:

| Поле | Значение |
|---|---|
| Тип | App, не Game |
| Язык по умолчанию | English (United States) |
| Название | `GasApp: Encrypted Chat` |
| Платное или бесплатное | Free |
| Категория | Communication |
| Реклама | No ads |
| Контакт пользователей | `support@gasapp.eu` — сначала проверьте приём писем |
| Android package name | `org.gasapp.app.gms` (flavor `gms`) |
| Минимальный Android | Android 9 / API 28 |
| Target SDK | API 36 |

При создании подтвердите декларации, которые предлагает сама консоль,
и условия Play App Signing. [Официальные шаги создания](https://support.google.com/googleplay/android-developer/answer/9859152).

**Не загружайте сборку debug или flavor `foss`:** для Play нужен
`bundleGmsRelease` из шага 24. Не создавайте второе приложение с другим
package name — после публикации идентификатор меняется только через новую
карточку приложения.

## 4. Что приготовить для проверки

* **Иконка:** PNG 512×512, до 1 MB.
* **Feature graphic:** JPG или PNG без прозрачности, 1024×500.
* **Скриншоты телефона:** минимум два настоящих экрана приложения; для
  карточки запланированы список чатов, переписка, сверка ключей, канал,
  настройки приватности. Только вымышленные переписки и имена.
* **App access:** рабочие обзорные аккаунты и канал, перечисленные в
  [инструкциях для ревьюера](en/google-play.md#5-app-access-reviewer-instructions).
  Замените заглушку ссылки на тестовый канал перед отправкой.
* **Страны:** по ранее принятому решению исключить Францию, пока нет
  требуемой декларации по шифрованию.
* **Тестирование:** для нового личного аккаунта перед доступом к
  production требуется закрытый тест с минимум 12 участниками, которые
  остаются подключены непрерывно 14 дней. Подготовьте их заранее.

Размеры графики: [правила Google](https://support.google.com/googleplay/android-developer/answer/9866151).
Тестирование: [правила личных аккаунтов](https://support.google.com/googleplay/android-developer/answer/14151465).

## 5. Блокирующие пункты перед отправкой

1. **Внешнее удаление:** Google требует ссылку, по которой человек может
   **отправить запрос** на удаление без повторной установки приложения.
   Нынешняя страница только объясняет невозможность такого запроса.
   Нужен безопасный процесс проверки владельца, который не позволит
   удалить чужой аккаунт. До его появления не отмечайте соответствующий
   пункт Data safety как выполненный.
2. Шаг 24: создать и проверить upload key, заменить заглушки TLS-пинов,
   собрать и протестировать подписанный `gms` AAB.
3. Проверить на двух телефонах регистрацию, письмо с кодом, сообщения,
   жалобы, удаление аккаунта и публичные документы.
4. Подготовить графику и живые обзорные аккаунты, убедиться, что
   `support@`, `privacy@`, `abuse@`, `security@` получают почту.
5. Проверить соглашение об обработке данных с почтовой службой и
   правильность декларации Data safety для финальной сборки.

Требование к веб-удалению: [официальная справка Google](https://support.google.com/googleplay/android-developer/answer/13327111).
Страницы и декларации: [App content](https://support.google.com/googleplay/android-developer/answer/9859455).
