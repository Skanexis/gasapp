## Остаточные риски — осознанно не закрыты кодом

* **Заполнение общего хранилища вложений.** Потолок 64 ГБ, работа
  за мегабайт постоянна (2¹⁶ хешей): заполнить его стоит минут видеокарты
  и 64 ГБ трафика, после чего вложения не принимаются у всех до истечения
  срока (30 суток). Proof-of-work этого не остановит; остановит
  ограничение по адресу на балансировщике (`limit_req`, `limit_conn`)
  и наблюдение за заполнением.
* **Захват имён.** Регистрация — 20 бит работы: секунда на телефоне,
  доли миллисекунды на видеокарте. Скупить короткие и словарные имена
  дёшево; брошенные освобождаются через 12 месяцев, но их можно держать.
  Решения — политика: зарезервированные имена, дороже короткие имена.
* **Молчащее соединение после TLS** (ни одного байта запроса) узел сам
  не закрывает: таймер заголовков в hyper взводится с первого байта.
  В боевой схеме его режет nginx (`client_header_timeout`); без
  балансировщика узел наружу выставлять нельзя.
* **Пины релизной сборки — заглушки** (`release/res/xml/network_security_config.xml`):
  так задумано, релиз с ними не соединится ни с чем. Заменить при
  первом боевом развёртывании — блокер релиза, не беты на своём узле.
* **Ограничения по адресу против Tor.** Tor — по умолчанию, и многие
  пользователи приходят с одного выходного узла: `limit_req` для
  discovery (20 в минуту на адрес) может задевать их вместе. Следить
  по 429 в первые недели беты.

## Открытые находки — найдены позже, не исправлены

Найдены 2026-09-30 при уборке репозитория: тесты от внутреннего аудита
2026-09-21 лежали в брошенной рабочей копии и в основную ветку не
попали. Прогнаны против текущего кода — падают. Сохранены как
выключенные тесты (`#[ignore]` с номером находки): исправлено — снять
`ignore`.

* **W-1. Прежнее состояние храповика живёт в журнале WAL.**
  `save_session` пишет `INSERT OR REPLACE` без контрольной точки, и
  прежняя версия страницы с состоянием сессии остаётся кадром в `-wal`
  до ближайшей точки. Тот, у кого есть ключ базы и снимок файлов,
  обрезает журнал по более ранней фиксации — и SQLite сам отдаёт
  прежнее состояние, то есть уже израсходованные ключи цепочки
  (спецификация §10.1 обещает их уничтожение). Удаление переписки
  точку уже делает (`checkpoint_truncate`), сохранение сессии — нет.
  Исправление — точка после сохранения сессии; цена — запись на
  каждое сообщение, решение по производительности.
  Тест: `crates/aegis-storage/tests/audit_wal.rs`.
* **B-1. Удалённое сообщение возвращается из усечённой цепочки копий.**
  Надгробие удаления живёт в инкременте; у цепочки нет подписанного
  признака «последнее звено». Хранилище копий (облако), не умея их
  прочесть, может отдать цепочку без хвоста — восстановление проходит
  и возвращает сообщение, удалённое «у всех». Исчезающие сообщения
  убирает чистка по сроку сразу после открытия, удалённые вручную —
  нет. Исправление — аутентифицированная длина цепочки (или новый
  полный снимок после удалений).
  Тест: `crates/aegis-core/tests/audit_backup.rs`.

## Проверено и находкой не оказалось

| Что | Почему не находка |
|---|---|
| Отправка неподтверждённому ключу в обход экрана | Ядро само отказывает (`PeerUnconfirmed`) на всех путях: текст, вложения, реакции, «печатает», квитанции |
| Сверка safety number сканированием | Сравниваются все 60 цифр целиком; только камера, без импорта картинки. Подсунутый злоумышленником QR при сверке не вживую — свойство любой схемы safety number, закрывается правилом «сверять лично» |
| Экспортированный экран входа | Ничего не читает из интента — перенаправлять нечего |
| Размер ответа сервера на клиенте | Ограничен: 64 МБ текст, 128 МБ блоб; кадры сокета — 64 КБ |
| Перепривязка аккаунта повтором | `recovered_at` обязан расти — повтор отвергается |
| Запись полученного вложения | Через системный диалог сохранения (SAF) — путь выбирает человек |
| Логи, WebView, изменяемые `PendingIntent` | Нет ни одного |
