# Воспроизводимые сборки и публикация SHA-256

Пункты M8 «Reproducible builds для Android» и «Подпись релизов +
публикация SHA-256» (раздел 22), ADR-020, MASVS RESILIENCE-2.2.

> **Статус: не достигнуто.** Закреплено окружение и заведены
> инструменты; сама побайтовая воспроизводимость APK не проверена.
> Что именно мешает — в разделе «Открытые источники расхождений».
> Отметка в плане не ставится, пока две независимые сборки не дадут
> одинаковую сумму.

## Зачем

🔐 Воспроизводимость — **единственная проверяемая связь** между
опубликованным исходным кодом и тем APK, который люди ставят на
телефон. Без неё «открытый код» означает лишь то, что код можно
прочитать, а не то, что собран именно он.

Для мессенджера это не абстракция. Подменить сборку можно тремя
способами, и все три реальны: скомпрометированная машина сборщика,
подмена в магазине приложений, принуждение выпускающего выдать особый
APK одному человеку. Против всех трёх работает одно: любой может
собрать тот же исходник и сверить сумму.

Это же — основная мера MASVS RESILIENCE-2 (anti-tampering). Проверка
подписи APK во время выполнения и обфускация лишь поднимают цену;
воспроизводимость даёт ответ «да» или «нет».

## Что уже закреплено

| Что | Где | Проверка |
|---|---|---|
| Версия Rust | `rust-toolchain.toml` | Cargo отказывается собирать другой |
| Версия NDK | `tools/Dockerfile.android` (r27c) и `android/app/build.gradle` (27.2.12479018) | `tools/check-ndk-pins.sh` |
| Версии зависимостей Rust | `Cargo.lock` + точные `=` в `Cargo.toml` | `cargo-deny` |
| Версии Gradle и AGP | `gradle-wrapper.properties`, `android/build.gradle` | — |
| Набор ABI | `abiFilters`, четыре штуки | — |
| Источники артефактов | `settings.gradle`, `FAIL_ON_PROJECT_REPOS` | Gradle роняет сборку |
| Время сборки | `SOURCE_DATE_EPOCH` из времени коммита | `tools/reproducible-build.sh` |
| Пути в бинарнике | `--remap-path-prefix` | там же |

⚠️ **Две версии NDK обязаны совпадать.** Контейнер собирает
`libaegis.so`, Gradle её обрезает (`strip`) — обе операции входят
в итоговый артефакт. До M8 они расходились: контейнер брал r27c,
Gradle требовал 29.0.14206865, к тому же preview-выпуск. Обе сборки
были успешны и давали разные байты. Теперь совпадение проверяется
скриптом.

## Как собрать

```bash
# 1. Ядро — только в контейнере: на хосте результат зависит от
#    системного OpenSSL и libc.
docker build -f tools/Dockerfile.android -t aegis-android tools/
docker run --rm -v "$PWD":/work -w /work aegis-android \
    tools/build-rust-android.sh

# 2. APK и суммы.
tools/reproducible-build.sh
```

Результат — `android/app/build/outputs/SHA256SUMS.txt`.

## Как сверить чужую сборку

```bash
git checkout <тег релиза>
tools/reproducible-build.sh --verify SHA256SUMS-release.txt
```

Расхождение означает одно из трёх: другая ревизия, другое окружение
сборки или подменённый артефакт. Третье обязано разбираться как
инцидент.

## Открытые источники расхождений

Перечислены честно: пока хоть один открыт, воспроизводимость
не достигнута.

1. **Baseline-профиль ART.** AGP собирает `compileReleaseArtProfile`
   из порядка классов, который между запусками не гарантирован.
   Обходится отключением профиля в релизе — ценой первого запуска
   на холодную. Решение не принято.

2. **Подпись.** Подписанный APK отличается от неподписанного, поэтому
   суммы считаются **до** подписи. Иначе сверять мог бы только тот,
   у кого есть ключ, то есть никто посторонний. Сверять подписанный
   APK нужно иначе — через `apksigner verify --print-certs` плюс
   сравнение содержимого архива без блока подписи; это не сделано.

3. **Сборка вне контейнера.** На хосте с другим OpenSSL результат
   отличается. Эталонной считается только сборка из
   `tools/Dockerfile.android`.

4. **Не проверено на практике.** Двух независимых сборок, давших
   одинаковую сумму, ещё не было. До этого всё написанное выше —
   намерение, а не факт.

## Подпись релиза

Настроена в `android/app/build.gradle` (`signingConfigs.release`).
Все четыре значения приходят из свойств Gradle — из
`~/.gradle/gradle.properties` или из переменных окружения CI:

```
aegisKeystore=/путь/к/aegis-release.jks
aegisKeystorePassword=…
aegisKeyAlias=aegis
aegisKeyPassword=…
```

🔐 Ни ключа, ни паролей в репозитории нет; `gitleaks` проверяет это
на каждом PR. Без свойств блок подписи не объявляется вовсе — пустой
`signingConfig` заставил бы AGP подписать релиз отладочным ключом
и выдать его за подписанный.

v1-подпись (JAR signing) выключена намеренно: `minSdk = 28`, а v2
существует с API 24, поэтому v1 не нужна ни одному поддерживаемому
устройству — зато оставляет в APK второй, более слабый путь проверки.

## Где публикуются суммы

Workflow `release.yml` собирает релиз, считает суммы и прикладывает
`SHA256SUMS.txt` к GitHub Release. 🔐 Суммы обязаны публиковаться
там же, где APK, **и** дублироваться в независимом месте: файл сумм
рядом с подменённым файлом подменяется так же легко.

Второе место пока не выбрано — открытый пункт.
