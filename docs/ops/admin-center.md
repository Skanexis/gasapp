# Админ-центр оператора

**Редакция:** 2026-10-07. Программа — `server/gasapp-server-admin`.

Админ-центр нужен оператору сервера для четырёх дел: разбирать жалобы,
видеть состояние сервиса, публиковать отчёт о прозрачности и выдавать
премиум. Он устроен так, чтобы **не расширять** того, что сервер знает
о людях.

## 🔐 Что админ-центр показывает и чего не показывает

| Показывает | Не показывает — этого нет и в базе |
|---|---|
| Числа: аккаунты, устройства, очередь, вложения, место, эпоха журнала ключей | Переписку, вложения в читаемом виде |
| Аккаунты с жалобами: имя, **число** разных жалобщиков, время жалоб с точностью до часа, месяц последней активности | Кто именно пожаловался |
| Аккаунт по **точному** имени: есть ли премиум, сколько у него каналов | Перечень всех пользователей |
| — | Адреса почты: в базе только хеш, и админ-центр его не показывает |
| — | Название и записи каналов (в базе шифротекст), кто их читает |
| Журнал своих действий: что, почему, сколько жалобщиков | Имена удалённых — после удаления об аккаунте не остаётся ничего |
| — | IP-адреса, историю входов, время сообщений, кто кому пишет |

Жалоба доказана: приложение отправляет **сертификат отправителя** с его
запечатанного конверта, подписанный сервером (`/v1/sealed/report`).
Пожаловаться можно только на того, кто действительно писал, и один
человек на одного отправителя — один раз.

## Премиум

Премиум — пометка на аккаунте, которая даёт одно право: **создавать
каналы**. Читать каналы может любой. Оплаты в приложении нет: премиум
выдаёт оператор вручную.

* **В админ-центре:** **Account** → точное имя → **Grant premium** /
  **Revoke premium and remove bots**. В карточке видно, есть ли премиум и сколько у
  аккаунта каналов.
* **Из командной строки** (на машине с админ-центром, с `DATABASE_URL`):

  ```bash
  gasapp-server-admin premium grant anna_k
  gasapp-server-admin premium revoke anna_k
  ```

Что нужно знать:

* снятие премиума запрещает создавать новые каналы, но не отнимает уже
  созданные: автор продолжает в них писать;
* у аккаунта не больше 10 каналов;
* выдача премиума в журнал действий и в отчёт о прозрачности не
  попадает — это не решение по жалобе;
* 🔐 оператор не видит, что написано в каналах, и не может узнать, кто
  их читает. Канал исчезает только вместе с аккаунтом автора (или когда
  автор удалит его сам).

## Установка

Быстро — `server/deploy/admin.sh --install` (поставить или обновить) и
`server/deploy/admin.sh` (открыть через туннель). Ниже — что эти команды
делают по шагам.

Админ-центр — отдельная программа рядом с базой, не часть публичного API:
в интернет не выставляется никогда.

```bash
# 1. Токен оператора — длинный, случайный, хранится у оператора.
openssl rand -hex 32 > ~/gasapp-admin-token        # держать в менеджере паролей

# 2. В окружение сервера кладётся только его хеш.
gasapp-server-admin hash-token < ~/gasapp-admin-token
# → 64 шестнадцатеричных знака → GASAPP_ADMIN_TOKEN_SHA256

# 3. Запуск (systemd-юнит или контейнер рядом с базой).
DATABASE_URL=postgres://… \
GASAPP_ADMIN_TOKEN_SHA256=<хеш> \
GASAPP_ADMIN_BIND=127.0.0.1:8480 \
gasapp-server-admin serve
```

`GASAPP_ADMIN_BIND` принимает только петлю (`127.0.0.1`, `::1`): другой
адрес — отказ запуска.

## Мониторинг серверов (Beszel)

Графики CPU, памяти, дисков и сети всех машин — Beszel 0.21.1:

```bash
bash /mnt/c/Users/be4ho/Desktop/WORK/AEGIS/server/deploy/beszel.sh
```

* Центр — на БАЗЕ, только `127.0.0.1:8090`; `admin.sh` пробрасывает его
  тем же туннелем, пункт «Servers» в меню админ-центра.
* Агенты — на всех машинах, слушают только адрес WireGuard; брандмауэр
  пускает к ним только базу; агент пускает только ключ центра.
* Ни центру, ни агентам нельзя в интернет (`IPAddressDeny` в службах).
* Программы — с проверкой SHA-256 по списку сумм выпуска. Обновление —
  сменить `VERSION` в `beszel.sh` (не моложе двух недель) и запустить.
* Оповещения о сбоях по-прежнему шлёт монитор в Telegram; Beszel —
  графики и история.

## Вход

Интерфейс оператора на английском. На широком экране разделы **Overview**,
**Reports**, **Account** и **Transparency** находятся в боковой панели;
на телефоне — в компактной навигации. Жалобы на телефоне показаны
карточками; остальные длинные таблицы прокручиваются внутри своего блока.
Действия удаления по-прежнему требуют явной отметки
о необратимости; на экране **Reports** форма удаления раскрывается отдельно
от действия **Dismiss reports**. Сводка показывает очередь жалоб на аккаунты,
а экран **Reports** — отдельные числа по аккаунтам и каналам.

С машины оператора — через SSH-туннель:

```bash
ssh -L 8480:127.0.0.1:8480 admin@<узел-с-админ-центром>
# браузер: http://127.0.0.1:8480
```

Или через onion-сервис, ведущий на `127.0.0.1:8480` (отдельный от
onion-адреса сервера, с клиентской авторизацией Tor). HTTP внутри
туннеля — нормально: SSH и Tor шифруют сами.

Защита входа:

* сравнение хеша токена за постоянное время;
* пять неверных токенов подряд закрывают вход на 10 минут;
* сессия — только в памяти процесса, простой 30 минут; перезапуск
  админ-центра выходит из всех сессий;
* cookie `HttpOnly`, `SameSite=Strict`; у каждой формы свой токен CSRF;
* заголовки: CSP без скриптов, запрет встраивания, `no-store`,
  `no-referrer`;
* 🔐 `Host` — только петля (`127.0.0.1`, `localhost`, `[::1]`) или
  `.onion`, иначе `421`: чужой сайт, чьё имя переназначено на 127.0.0.1
  (DNS rebinding), с админ-центром не говорит. `Origin` у POST — только
  свой, иначе `403`: прежде чужая страница, открытая в браузере
  оператора, отправляла форму входа с неверными токенами и закрывала
  вход на 10 минут сколько угодно раз (аудит 2026-10-02, S-5).

## Уведомления о жалобах

```cron
*/10 * * * * DATABASE_URL=… GASAPP_NOTIFY_CMD="/opt/gasapp/notify-telegram.sh" gasapp-server-admin watch-reports
```

В уведомлении — только число новых жалоб: имена оператор смотрит в самом
админ-центре. Канал уведомлений (Telegram, почта) — чужая служба, и имени
там быть не должно. `GASAPP_NOTIFY_CMD` — та же команда, что у
`deploy/check-nodes.sh` (текст — на stdin).

## Порядок работы с жалобами

**Срок — 24 часа** с жалобы. Это обещание Apple (Review Notes) и
пользователям (`docs/store/child-safety-standards.md`), и держать его —
обязанность оператора.

1. **Жалобы** — список отсортирован по числу разных **сертификатов**,
   затем жалобщиков.

   ⚠️ Сертификат отправителя — предъявительский (аудит 2026-10-02, S-4):
   получивший **одно** сообщение может пожаловаться с десятка своих
   аккаунтов (регистрация — секунды работы), и это выглядит как десять
   жалобщиков. Отличает накрутку столбец «Сертификатов»: сертификат
   действует сутки, и настоящий спам, разосланный многим и в разные
   дни, приходит под разными сертификатами, а накрутка одним
   сообщением — под одним. **Много жалобщиков при одном сертификате —
   не основание удалять** без письма на `abuse@`. Жалобы, записанные
   до миграции 0016, сертификата не помнят и в этом столбце не
   считаются.
2. Решение по каждому аккаунту:
   * **Удалить аккаунт** — с причиной: спам, травля, CSAE, выдаёт себя
     за другого, иное незаконное, прочее. Удаление — то же, что удаление
     владельцем: аккаунт, устройства, ключи, очередь, жалобы уходят
     сразу. Имя освобождается.
   * **Отклонить жалобы** — жалобы удаляются, аккаунт остаётся.
3. Содержимого переписки у оператора нет и не будет. Решение принимается
   по числу независимых жалобщиков и сертификатов и по тому, что человек прислал
   сам (письмо на `abuse@` со снимками экрана).

**CSAE (сексуальное насилие над детьми)** — немедленно, без ожидания
второго жалобщика, если есть основание (письмо, снимки):

1. удалить аккаунт с причиной «Насилие над детьми (CSAE)»;
2. сообщить в компетентный орган страны сервера: в ЕС — национальная
   горячая линия сети INHOPE, в США — NCMEC (CyberTipline);
3. передать то, что есть у сервера: имя, открытые ключи, месяц
   активности — **до удаления**, если орган этого требует (удаление
   необратимо, после него передавать нечего).

## Отчёт о прозрачности

Раздел **«Прозрачность»** — действия по месяцам: сколько аккаунтов
удалено и за что, сколько жалоб отклонено, сколько было жалобщиков.
Имён нет. Эти числа публикуются раз в квартал рядом с политикой
конфиденциальности.
