# Тестовые векторы протокола GasApp

Состояние на 2026-08-13.

## Два вида векторов, которые нельзя путать

**Эталонные** — из независимого источника: текста RFC, публикации NIST или
другой реализации. Совпадение с ними означает **совместимость**: наш код
делает то же, что эталон.

**Регрессионные** — получены нашей же реализацией и зафиксированы, чтобы
поймать непреднамеренное изменение алгоритма. Совместимости они не
доказывают: ошибку, присутствовавшую с самого начала, такой вектор
зафиксирует, а не обнаружит.

Каждый файл в этом каталоге явно отмечает, к какому виду относится.

| Каталог | Вид | Источник | Проверяется |

## Чего нет — и почему это важно

**Эталонных векторов самого протокола: PQXDH, Double Ratchet, SPQR.**

### Почему их нельзя взять из libsignal

ADR-005 предполагал снять векторы с libsignal в изолированном контейнере.
**Проверка 2026-08-14 показала, что это невозможно** — и причина не
лицензионная, а техническая: GasApp и libsignal реализуют **разные
протоколы**, а не разные реализации одного.

Сверка выполнена по исходникам libsignal `main` (склонированы в контейнер,
в репозиторий ничего не копировалось):

| Что | GasApp | libsignal |
|---|---|---|
| Метка KDF в PQXDH | `GASAPP_PQXDH_v2_X25519_MLKEM1024_TRANSCRIPT` (соль — хеш транскрипта; v1 с нулевой солью — до 2026-09-24) | `WhisperText_X25519_SHA-256_CRYSTALS-KYBER-1024` |
| Метка корневого ключа | `GASAPP_DR_v1_ROOT` | `WhisperRatchet` |
| Метка ключа сообщения | HMAC с константами `0x01`/`0x02` | `WhisperMessageKeys` через HKDF |
| Шифрование сообщения | AES-256-GCM (AEAD) | AES-CBC + отдельный HMAC |
| KEM в ratchet | ML-KEM-768 | Kyber-1024 |
| Гибридное объединение | `HKDF(MK_classic ‖ MK_pq)` | иная схема связывания `pqr_key` |

Метка KDF входит в вывод ключа. Даже при одинаковых входных ключах разные
метки дают разные выходы — по построению HKDF. Совпадения быть не может
**ни в одном** векторе, и его отсутствие ничего не докажет: расхождение
ожидаемо и не отличимо от ошибки реализации.

Это не дефект GasApp и не дефект libsignal. Домены разделены намеренно
(раздел 6.2): протоколы не должны производить одинаковые ключи, иначе
материал одного можно было бы подставить в другой.

### Что это значит на практике

Дифференциальное тестирование против libsignal как оракула **невыполнимо**
без приведения GasApp к меткам и конструкциям Signal, то есть без отказа
от собственного протокола. Такое решение — предмет ADR, а не задача
верификации.

Проверка выполнена так: libsignal склонирован **в контейнер**, прочитан
и удалён; в репозиторий не попало ни строки его кода. Лицензионная схема
ADR-005 при этом соблюдена — но выяснилось, что применять её не к чему.

Остаются два пути, оба открыты:

1. **Вторая независимая реализация GasApp** по спецификации
   `docs/protocol/GASAPP-PROTOCOL-v1.md` — написанная по документу, а не
   по коду. Расхождение указывало бы либо на ошибку реализации, либо на
   неоднозначность спецификации; и то, и другое ценно.
2. **Формальная модель** handshake (ProVerif/Tamarin) — она проверяет
   свойства протокола, а не байтовое совпадение, и не требует оракула.

Пока ни одного из них нет, PQXDH, Double Ratchet и SPQR проверены только
сами на себе. Ошибка, симметрично допущенная в обеих ветках кода —
например, одинаково перепутанный порядок аргументов KDF при шифровании и
расшифровке, — такими тестами не ловится: round-trip проходит,
а совместимость потеряна.

Это главный незакрытый риск M2, и он **не снимается** запуском Docker.

## Формат

Файлы читаются человеком и сверяются глазами с первоисточником, поэтому
формат намеренно простой: одно поле на строку, hex без разделителей,
комментарии с `#`. Пустое значение — пустая строка после двоеточия.

Значения дублируются в коде тестов: файл здесь нужен для сверки
с первоисточником, а тест — для того, чтобы расхождение ломало сборку.
