# Проверка на двух телефонах

APK собирается по шагу 3. Сборки под прежним именем (AEGIS) для этого
стенда больше не годятся: пакет приложения, метки протокола и подпись
запросов сменились вместе с именем 2026-10-07.

## Что нужно

- Два Android-телефона, оба в **той же сети Wi-Fi**, что и компьютер
- Компьютер с адресом **192.168.1.15** (проверьте: `ipconfig`)

Адрес зашит в сертификат сервера и в пин клиента. Если адрес другой,
см. раздел «Если адрес изменился».

## 1. Поднять сервер

Postgres живёт в WSL, сервер — на Windows.

```bash
# Postgres
wsl -d Ubuntu-24.04 --user root -e service postgresql start

# Сервер (из каталога server/)
GASAPP_ALLOW_INSECURE=1 \
GASAPP_DEV_EMAIL_CODE=123456 \
GASAPP_CERTIFICATE_KEY=$(openssl rand -hex 32) \
GASAPP_EMAIL_KEY=$(openssl rand -hex 32) \
GASAPP_TLS_CERT=deploy/tls/cert.pem \
GASAPP_TLS_KEY=deploy/tls/key.pem \
DATABASE_URL=postgres://gasapp:gasapp-dev@127.0.0.1:5432/gasapp \
cargo run -p gasapp-server-api --bin gasapp-server-api
```

В логе должно появиться `сервер GasApp слушает по TLS`.

**Про почту на стенде.** Регистрация требует кода из письма, а почтовой
службы на стенде нет. `GASAPP_DEV_EMAIL_CODE=123456` делает код
постоянным: письмо не уходит, в приложении вводится `123456`, адрес
годится любой правдоподобный (`anna@example.org`). Переменная действует
только вместе с `GASAPP_ALLOW_INSECURE=1` — боевой сервер её не читает.
Без неё сервер пишет случайный код в свой журнал
(`ПИСЬМО НЕ ОТПРАВЛЕНО — код подтверждения`).

⚠️ `GASAPP_CERTIFICATE_KEY` и `GASAPP_EMAIL_KEY` в примере новые при
каждом запуске — для стенда, который каждый раз начинается с пустой
базы. Если база переживает перезапуск, задайте постоянные значения:
со сменой ключа почты прежние адреса станут «свободными».

Проверка с компьютера:

```bash
curl -sk https://192.168.1.15:8443/v1/discovery/username/nobody -w '%{http_code}\n'
# 404 — сервер отвечает (имени нет, это правильно)
```

## 2. Открыть порт в брандмауэре

Windows по умолчанию не пускает входящие соединения. **Из PowerShell
от администратора**:

```powershell
New-NetFirewallRule -DisplayName "GasApp server" -Direction Inbound `
    -LocalPort 8443 -Protocol TCP -Action Allow
```

Без этого телефоны увидят «Сервер недоступен».

## 3. Собрать APK под нужный адрес

APK на рабочем столе собран под `10.0.2.2` — это адрес для эмулятора.
Для телефонов нужен адрес в локальной сети:

```bash
cd android
./gradlew assembleFossDebug -PgasappServerUrl=https://192.168.1.15:8443
```

Готовый файл: `android/app/build/outputs/apk/foss/debug/app-foss-debug.apk`

## 4. Установить на телефоны

Через кабель:

```bash
adb install -r app-foss-debug.apk
```

Либо скопировать файл на телефон и открыть его — потребуется разрешить
установку из неизвестных источников.

## 5. Проверить обмен

1. На **первом** телефоне: открыть приложение → «Создать аккаунт» →
   имя (например `anna`) и почта (`anna@example.org`) → «Продолжить» →
   PIN → «Продолжить». Займёт несколько секунд — идёт подбор
   proof-of-work. Затем код `123456` → «Создать аккаунт».
   В сети, где Tor блокируют, на шаге имени включите «Подключаться
   напрямую, без Tor».
2. На **втором**: то же самое с другим именем и другим адресом
   (например `boris`, `boris@example.org`) — один адрес даёт один
   аккаунт.
3. На первом: кнопка с карандашом справа внизу → ввести `boris` →
   «Открыть» → написать сообщение → «Отправить».
4. На втором: открыть чат с `anna` — сообщение придёт при открытии
   экрана.

## 6. Проверить каналы

1. Выдать первому аккаунту премиум (из каталога `server/`):

   ```bash
   DATABASE_URL=postgres://gasapp:gasapp-dev@127.0.0.1:5432/gasapp \
   cargo run -p gasapp-server-admin -- premium grant anna
   ```

2. На первом телефоне: вкладка «Каналы» → «+» → название → «Создать» →
   написать запись. Без премиума «+» показывает подсказку с `@именем`
   вместо формы.
3. Там же: значок ссылки в шапке канала → QR-код и ссылка.
4. На втором: «Каналы» → значок ссылки → «Сканировать QR-код» (или
   «Вставить ссылку») — канал открывается с записью.
5. На первом — ещё одна запись; на втором она появляется при открытии
   вкладки «Каналы» или самого канала.

Что сервер хранит о канале:

```bash
wsl -d Ubuntu-24.04 --user root -e su postgres -c \
  "psql -d gasapp -c 'SELECT seq, octet_length(body), posted_at FROM channel_posts;'"
```

Видно номер, размер (606 байт у короткой записи: бакет 512 плюс
заголовок) и час публикации — текста и названия канала в базе нет.

**Проверено на эмуляторе 2026-10-08** (Android 16, прямое соединение,
сервер и Postgres на той же машине): регистрация с кодом, отказ
в создании канала без премиума, создание канала после
`premium grant`, публикация записи, ссылка и QR-код, вход по PIN после
перезапуска. **Не проверено** на этой машине: вход во второй аккаунт
по ссылке на реальном втором устройстве, работа через Tor (сеть
разработки его блокирует), возврат к шагу кода после автоблокировки.

## Что проверить, что сервер не читает переписку

```bash
wsl -d Ubuntu-24.04 --user root -e su postgres -c \
  "psql -d gasapp -c 'SELECT length(ciphertext), encode(substring(ciphertext from 1 for 16), \"hex\") FROM envelopes;'"
```

Видно только длину и случайные байты. Поиск текста сообщения по
полному дампу базы ничего не находит:

```bash
wsl -d Ubuntu-24.04 --user root -e su postgres -c "pg_dump gasapp" | grep -c "ваш текст"
# 0
```

## Если адрес изменился

Сертификат выписан на `192.168.1.15`. При другом адресе нужно
перевыпустить его и обновить пин:

```bash
# 1. Новый сертификат
cd server/deploy/tls
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem \
    -days 365 -subj '/CN=НОВЫЙ_АДРЕС' \
    -addext 'subjectAltName=IP:НОВЫЙ_АДРЕС,IP:10.0.2.2,IP:127.0.0.1'

# 2. Новый пин
openssl x509 -in cert.pem -pubkey -noout | openssl pkey -pubin -outform der \
    | openssl dgst -sha256 -binary | openssl enc -base64
```

Полученную строку вписать **в оба** тега `<pin>` в файле
`android/app/src/main/res/xml/network_security_config.xml`, а адрес —
в теги `<domain>`. Затем скопировать `cert.pem` в
`android/app/src/main/res/raw/gasapp_local_ca.crt` и пересобрать APK.

## Что не работает

Честный список на сегодня:

- **Приём только при открытии чата.** Фонового получения и уведомлений
  нет — WebSocket-хаб не написан. Чтобы увидеть новое сообщение, нужно
  открыть переписку.
- **PIN не защищает хранилище.** Экран блокировки принимает любые шесть
  цифр: растягивание PIN через Argon2id (`gasapp-keystore`) ещё не
  подключено к открытию базы. База зашифрована, но известным ключом —
  то есть защищена от случайного чтения, а не от изъятия устройства.
- **Список чатов показывает демо-данные.** Lena Novak и остальные —
  заглушка из макета. Настоящие чаты видны после того, как напишете
  через кнопку нового чата.
- **Safety number не сверяется по-настоящему.** Экран показывает число,
  но отметка «верифицирован» пока не сохраняется.
- **Сертификат самоподписанный.** Для боевого сервера нужен домен
  и сертификат от удостоверяющего центра.
- **Аудита не было.** Это написано и на экране приветствия: не
  используйте для защиты жизни и свободы.
