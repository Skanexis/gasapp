# Черновики движков протокола — НЕ подключены к сборке

Файлы в этом каталоге переименованы в `*.rs.draft`, чтобы `cargo` не собирал
их и чтобы их нельзя было подключить одной строкой в `lib.rs`, не прочитав
сначала это предупреждение.

## Почему они здесь, а не в `src/`

При сверке 2026-08-13 (раздел 23.0 мастер-плана) выяснилось, что
`gasapp-protocol` давал 136 ошибок компиляции и никогда не собирался.
Примитивы (`x25519`, `xeddsa`, `mlkem`) переписаны и закрыты векторами
RFC 7748, RFC 8032 и FIPS 203. Движки — нет, и вот почему.

Помимо ошибок сборки в них есть дефекты, **которые компилятор поймать не
может**. Они пережили бы «починку до состояния, когда компилируется»,
и результат выглядел бы как работающий протокол:

| Файл | Дефект | Почему это критично |
|---|---|---|
| `pqxdh.rs.draft` | Подписи предключей проверяются **нашим** `our_identity`, а не `their_bundle.identity_key` | Аутентификация bundle отсутствует. Сервер может подменить SPK/PQSPK любого контакта. Раздел 6.2 требует прервать установление сессии при несходящейся подписи, без «мягкого» режима |
| `pqxdh.rs.draft` | При исчерпанном OPK в `ikm` подмешивается `dh4 = [0u8; 32]` | Раздел 6.2 требует, чтобы DH4 **отсутствовал**, а не был нулевым блоком |
| `spqr.rs.draft` | `// In a full implementation, we would combine the shared secrets` | «Критичные 15 строк» `HKDF(MK_classic ‖ MK_pq)` из ADR-021 не написаны. Triple Ratchet не гибридный: компрометация классической части ломает всё |
| все четыре | Реализуют `ProtocolEngine` с несовпадающими сигнатурами | Архитектурная ошибка: PQXDH, Double Ratchet и SPQR — **этапы одного протокола**, а не три взаимозаменяемых движка. Трейт (раздел 9.3) описывает протокол целиком |
| `spqr.rs.draft` | Заимствование `skipped_keys` при удалении (E0502) | Вытеснение по TTL написано неверно |
| `gasapp-core-lib.rs.draft` | `//!` (doc-комментарий модуля) внутри тела структуры, двойной `use gasapp_types::Secret`, импорт несуществующего `uniffi::Callback` | Крейт не компилировался ни разу; кроме того опирается на движки выше, поэтому чинится только после них |

## Про `gasapp-core`

Крейт `gasapp-core` (1048 строк) временно исключён из workspace и лежит здесь
двумя файлами: `gasapp-core-lib.rs.draft` и `gasapp-core-Cargo.toml.draft`.
Он оркеструет движки протокола, поэтому его починка бессмысленна до
закрытия M2 — восстанавливать его нужно последним.

⚠️ При возврате `gasapp-core` в workspace не забыть вернуть строку
`gasapp-core.workspace = true` в `crates/gasapp-ffi/Cargo.toml`: она была
удалена, потому что фактического `use gasapp_core` в коде FFI нет, а
зависимость тянула несобирающийся крейт и ломала всю границу FFI.

## Что с ними делать

Использовать как справочный материал при написании M2 заново — структура
модулей и разбиение на шаги местами разумны. Но **не** восстанавливать
построчно: дефект №1 и №3 воспроизведутся, а тесты под них писать никто
не станет, потому что код «уже работает».

Порядок работ по M2 — раздел 23.0.1 мастер-плана:

1. PQXDH: проверка подписей ключом отправителя + тесты на отказ
   (неверная подпись → сессия не устанавливается).
2. Double Ratchet: цепочки, out-of-order, `MAX_SKIP`, TTL.
3. SPQR: комбинирование секретов с обязательными тестами
   `test_classic_survives_pq_compromise` и
   `test_pq_survives_classic_compromise` — они обнаруживают дефект №3
   немедленно.

Каталог удаляется после закрытия M2.
