# Фаззинг GasApp

Шесть таргетов по поверхностям недоверенного входа.

## Быстрый старт

```powershell
pwsh fuzz/run-all.ps1                # 300 секунд на таргет
pwsh fuzz/run-all.ps1 -Seconds 3600  # часовой прогон
```

Первый запуск соберёт образ (~2.6 ГБ, несколько минут). Дальше он берётся
из кэша.

## Почему в контейнере, а не на хосте

libFuzzer требует clang-совместимых санитайзеров. На Windows MSVC
x64-библиотеки ASan (`clang_rt.asan_dynamic_runtime_thunk-x86_64.lib`)
в составе Visual Studio Build Tools 2019 **отсутствуют** — установлены
только 32-битные. Сборка компилируется, но падает на линковке:

```
LINK : fatal error LNK1104: cannot open file
       'clang_rt.asan_dynamic_runtime_thunk-x86_64.lib'
```

Сборка без санитайзера (`-s none`) не помогает: тогда не разрешаются
символы инструментирования покрытия `__stop___sancov_pcs`, которые
приходят из той же runtime-библиотеки.

Контейнер решает это, ничего не устанавливая на машину разработчика,
и заодно воспроизводит окружение ночного CI.

## Таргеты

| Таргет | Что разбирает | Источник входа |
|---|---|---|
| `chunk_reassembly` | ресборку чанков SPQR | сеть, подконтрольно отправителю |
| `parse_message` | заголовок и тело сообщения | сеть |
| `parse_content` | содержимое после расшифровки: текст, вложения, правки, ключ доступа | собеседник — его реализация, его длины |
| `decrypt_session` | сообщение + состояние сессии | сеть + повреждённая база |
| `parse_prekey_bundle` | prekey bundle | **сервер** — недоверенный по модели угроз |
| `parse_session_state` | сохранённое состояние | повреждённый файл базы |
| `parse_safety_number` | ввод safety number | человек: опечатки, обрезки, любой язык |
| `backup_restore` | архив резервной копии | хранилище копии — чужое |
| `parse_sealed_sender` | запечатанный конверт | сеть, отправитель не назван |
| `parse_contact_link` | ссылка `gasapp://contact/…` | кто угодно: ссылку присылают |

Из исходного списка плана `backup_restore` написан, а `deep_link`
и `qr_payload` покрывает `parse_contact_link`: QR профиля несёт ту же
ссылку `gasapp://contact/…`. ⚠️ До 2026-09 здесь было сказано, что все
три не написаны, `run-all.ps1` запускал шесть таргетов из девяти,
а разбора содержимого сообщения (`parse_content`) не фаззил никто.

## Первый прогон

**2026-08-14, все шесть таргетов по 300 секунд. Крашей нет.**

| Таргет | Запусков | Корпус |
|---|---|---|
| `parse_safety_number` | 249 272 030 | 62 |
| `parse_session_state` | 17 424 802 | 161 |
| `parse_prekey_bundle` | 4 886 151 | 45 |
| `chunk_reassembly` | 3 539 886 (за 121 с) | 727 |
| `parse_message` | — | 67 |
| `decrypt_session` | — | 216 |

Разброс на два порядка закономерен и сам по себе информативен. Быстрые
таргеты (`parse_safety_number`) отбрасывают вход на первом же нецифровом
символе. Медленные (`parse_prekey_bundle`) на каждой итерации выполняют
проверку подписи XEdDSA — это сотни тысяч операций, а не сравнение байт.
Малый корпус при большом числе запусков означает, что пространство
достижимых состояний невелико, а не что фаззер работал плохо.

Обратное тоже верно: у `chunk_reassembly` корпус самый большой (727),
потому что сборщик имеет настоящую машину состояний — эпохи, индексы,
частичные сборки, — и фаззер нашёл в ней много различимых путей.

**`parse_content`, 2026-09-22, 120 секунд:** 13 097 994 запуска, корпус 107,
покрытие 397. Крашей и расхождений туда-обратно нет. Запущен в образе
с явным `--entrypoint /usr/local/cargo/bin/cargo`: образ `gasapp-fuzz:latest`
на машине разработчика оказался собран не из `fuzz/Dockerfile` (без
`ENTRYPOINT`), и `run-all.ps1` на нём падает на каждом таргете.

Цель плана — 100M+ запусков на таргет до релиза. Достигнута пока только
для `parse_safety_number`; остальное набирается ночными прогонами в CI,
а не разовым запуском на машине разработчика.

## Прогон на стабильном компиляторе

`crates/gasapp-protocol/tests/fuzz_corpus.rs` прогоняет ту же логику
детерминированным генератором и идёт в обычном `cargo test`. Это **не
замена** фаззингу — нет обратной связи по покрытию, — но грубые паники
ловятся на каждом коммите, а не раз в сутки.

## Артефакты

Вход, воспроизводящий краш, сохраняется в `fuzz/artifacts/<таргет>/`.
Воспроизвести:

```powershell
docker run --rm -v "${PWD}:/gasapp" gasapp-fuzz:latest `
    run --fuzz-dir fuzz <таргет> fuzz/artifacts/<таргет>/<файл>
```

Корпус (`fuzz/corpus/`) и артефакты не коммитятся: корпус растёт
неограниченно и вне конкретного прогона смысла не несёт. В CI он
кэшируется между запусками.
